# Архитектура dsh-pet-cactus

## Слои

```
┌──────────────────────────── браузер (Web-GUI) ────────────────────────────┐
│  adapter.js   __ModuleLoader__.load → { name, inject, apply }              │
│      │        ctx.slots.register('shell.overlay', 1200, CactusLayer)       │
│      ▼                                                                    │
│  engine.js    DOM-движок: спрайт, плашки, drag, пузырь, /state            │
│      │                                                                    │
│  geometry.js  чистые функции: clamp, углы, позиция пузыря                  │
│  phrases.js   тексты по настроениям                                        │
└───────────────────────────────┬───────────────────────────────────────────┘
                                │ fetch, только localhost
┌───────────────────────────────▼───────────────────────────────────────────┐
│  host (lib/index.js)                                                      │
│    createHost()  состояние { mood, text, seq }, конфиг, обработчик HTTP    │
│    apply(ctx)    webServer.register(prefix) + ctx.on('session/event')     │
│      │                                                                    │
│  config.js       умолчания, валидация, атомарная запись                    │
│  tool-lines.js   «Стучу по терминалу» и компания                           │
└───────────────────────────────────────────────────────────────────────────┘
```

## Контракты DSH, на которые опирается плагин

| Механизм | Как используется | Если недоступен |
|---|---|---|
| `cordis.patch.yml` + `dsh.bundle.patch` | одна строка `dsh-pet-cactus` в дереве конфигурации | плагин просто не загружен |
| `ctx.webServer.register({ kind: 'prefix' })` | маршруты `/dsh-pet-cactus/*` | хост не стартует (inject обязателен) |
| `ctx.on('session/event')` | настроение по `turn/start`, `tool/call`, `approval/asked`, `turn/end` | питомец живёт на локальных умолчаниях |
| `ctx.effect` | снятие маршрутов, подписки и таймеров при выгрузке | утечка до перезапуска |
| `package.json → dsh.client` + `exports["./client"]` | DSH отдаёт `/plugins/dsh-pet-cactus/client.js` | браузерная половина не грузится |
| `window.__ModuleLoader__.load({ id, factory })` | регистрация клиентского модуля | предупреждение в консоль, страница жива |
| `ctx.slots.inject('shell.overlay', …)` | оверлей поверх интерфейса, `order: 1200` | предупреждение, остальное работает |
| `require('react')` внутри factory | компонент-обёртка на 20 строк | без React оверлей не рендерится |

Плагин не трогает внутренности DSH: не читает файлы харнесса, не импортирует
`@deepseek-ai/*`, не подменяет DOM-узлы хоста. Единственный непубличный риск —
форма событий `session/event`; она читается защитно (поле отсутствует → пропуск,
исключение → предупреждение в лог).

## Поток данных

1. DSH emits `session/event` → `onSessionEvent`.
2. Событие фильтруется: суб-агенты и `delegationDepth > 0` отбрасываются.
3. Настроение и текст пишутся в состояние; `seq` растёт только при реальном изменении.
4. Браузер раз в 3 с читает `/api/state`, сравнивает `seq` и, если он новый,
   переключает настроение. Никакого длинного поллинга и WebSocket: трафик — сотни
   байт, задержка до 3 с для игрушки приемлема.
5. Через 4 с рабочее настроение само возвращается в покой (таймер на хосте,
   `unref`, чтобы не держать процесс).
6. Клик, drag и сон обрабатываются целиком в браузере; на хост уходят только
   `GET /api/config` при загрузке и опрос `/api/state`.

## Решения и почему

**Один файл client.js, собранный склейкой.** Клиентской половине не нужна
транспиляция: нет JSX, нет импортов, React приходит через `require`. Бандлер
добавил бы 40 МБ devDependencies и шаг сборки, который ломается на чужой машине.
Склейка четырёх файлов даёт один артефакт и читаемый исходник. Порядок файлов —
контракт: геометрия → фразы → движок → адаптер.

**Движок без React.** Вся логика — обычный DOM. React нужен только чтобы
вписаться в слот DSH. Побочный выигрыш: превью открывается как файл в браузере,
а геометрия тестируется в Node без jsdom.

**Хост-настроение — подсказка, а не команда.** Без хоста (упал, не загрузился,
старая версия) кактус работает: клик, drag, фразы, сон. Это осознанная деградация:
питомец не должен зависеть от бэкенда.

**Свои ассеты.** Персонаж — растровый стикер (WebP 54 КБ), упакованный в бандл
data-URI; плашки и меню — DOM, поэтому текст живой и не зависит от картинки.
никаких лицензионных вопросов, масштабируется без потерь. Отсюда же ограничение:
нет покадровых анимаций, только CSS-трансформации.

**Валидация до записи.** `mergeConfig` возвращает `{ config, errors, unknown }`.
Маршрут сначала проверяет, потом пишет: отклонённый патч не может затереть файл
умолчаниями. Это же свойство проверяет тест «PUT с неверным типом… файл не появляется».

**Суб-агенты молчат.** Питомец — индикатор ожидания пользователя, а не лог
делегаций. Фильтр по `header.origin === 'subagent'` и `delegationDepth > 0`;
форма сессии читается защитно.

**Таймеры с `unref`.** Возврат в покой не должен мешать DSH завершиться.

## Инварианты

1. `apply()` не бросает: всё, что может отсутствовать, проверяется.
2. Все подписки и таймеры снимаются в `ctx.effect`.
3. Клиентская половина не делает запросов вне `/dsh-pet-cactus` и своего origin.
4. Тексты не содержат разметки и ограничены 140 символами.
5. `DEFAULTS` в `lib/config.js` и `src/client/engine.js` совпадают — это тест.
6. `lib/client.js` — производный артефакт; правки только в `src/client`.

## Тесты

| Файл | Что проверяет |
|---|---|
| `test/config.test.mjs` | умолчания, границы, типы, битый JSON, атомарность записи |
| `test/geometry.test.mjs` | clamp, углы, восстановление позиции, позиция пузыря |
| `test/routes.test.mjs` | все маршруты, коды ошибок, лимит тела, реакция на события, фильтр суб-агентов |
| `test/parity.test.mjs` | совпадение умолчаний, пулы фраз, реплики инструментов, один `load` в бандле |
| `test/adapter.test.mjs` | бандл сам зовёт `load`; `inject: ['slots']`; оверлей в `shell.overlay`; без React не падает |

`npm test` → `node scripts/test.mjs`: импорт файлов в один процесс, потому что
`node --test` в песочнице DSH не может породить дочерний процесс (`EPERM`).

## Чего нет и почему

- **Второго окна поверх рабочего стола.** Это требует Electron-хелпера на сотни
  строк и ломается при обновлениях DSH. Web-GUI закрывает задачу.
- **Модели и голоса.** Питомец не должен молча отправлять текст в чужой сервис.
- **Панели настроек в `settings.section`.** Пока хватает файла и `PUT`; панель —
  следующий шаг, она потянет React-формы и ещё один контракт.
- **Сторонних картинок и мемов.** Только свой спрайт в `assets/`.

## Дорожная карта

1. Панель `settings.section` с ползунками размера и переключателями.
2. Несколько экземпляров и «породы» (второй спрайт + свой набор фраз).
3. Опциональный звук клика (локальный файл, без сети).
4. Экспорт настроения наружу Cordis-сервисом, чтобы другие плагины могли
   использовать кактуса как индикатор.
